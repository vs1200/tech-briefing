今朝は **「モデルを手動で選ぶ」時代の終わりがさらに近づいたGitHub Copilot、DeepSeekの効率重視モデル、MCP初の公式資格、そして“開発サーバーを外に出すな”というかなり実務的なセキュリティ事故**が目立ちます。昨日まで扱ったClaude Plugin Evals、Real-SWE、PydanticAI Capabilitiesなどは外しました。

---

## 1. Copilot、自動モデル選択に「Efficiency / Balance / Intelligence」

[GitHub公式発表](https://github.blog/changelog/2026-09-14-configure-cost-and-quality-in-copilot-auto-model-selection/)

9月14日、[GitHub](https://github.com/) CopilotのAuto Model Selectionに、**3段階のQuality / Cost Policy**が追加されました。

**Efficiency** — Premium Request消費を抑える
**Balance** — 品質と消費量の中間
**Intelligence** — より高性能なモデルを優先

Enterprise管理者はOrganization全体のDefault Tierも指定できます。([The GitHub Blog](https://github.blog/changelog/2026-09-14-configure-cost-and-quality-in-copilot-auto-model-selection/))

**開発者目線:** かなり重要です。最近紹介したHydraFusionともつながっていて、

`Claude vs GPT vs Geminiを人間が選ぶ`

より、

`このTaskではCost重視 / Intelligence重視`

と**目的だけ指定してRouterに任せる**方向になっています。

長時間Coding Agentでは、モデル名より「Task Completion / Cost Policy」を設定する方が自然になりそうです。

## 2. DeepSeek V4.1-Flash — 次世代Architectureの小型・高速版

DeepSeek が **DeepSeek-V4.1-Flash** を公開しました。Reutersによれば、新しいV4.1 Architectureの最小モデルで、特にInference速度・Throughput・Scaling Efficiencyを重視しています。([Reuters](https://www.reuters.com/world/asia-pacific/chinas-deepseek-launches-v41-flash-model-2026-09-10/))

技術的にはCausal Encoder-Decoder、MoE、KV-cache圧縮など、**「モデルを巨大化する」よりInferenceを安くする**工夫がかなり多く入っています。([KDnuggets](https://www.kdnuggets.com/why-deepseek-v4-1-flash-is-such-an-exciting-open-model-release))

**開発者目線:** Agentでは1 Taskで数十〜数百回Model Callするため、最高Benchmarkより、

**十分賢い × 速い × 安い**

モデルの価値が非常に高いです。

最近のMuse Spark、HydraFusion、Copilot Efficiency Tierと合わせて、2026年後半は明らかに**Inference Efficiency競争**へ比重が移っています。

## 3. MCPに初の公式資格「MCPA」

[Linux Foundation公式発表](https://www.linuxfoundation.org/press/agentic-ai-foundation-launches-mcpa-certification-to-validate-mcp-expertise?hs_amp=true)

Agentic AI Foundationが **Model Context Protocol Associate（MCPA）** を発表しました。MCPに関する初の公式Certificationです。([Linux Foundation](https://www.linuxfoundation.org/press/agentic-ai-foundation-launches-mcpa-certification-to-validate-mcp-expertise?hs_amp=true))

内容は単なるMCP Serverの書き方ではなく、

Architecture / Client-Server Lifecycle / Transport / Tools / Resources / Prompts / Security / Authentication

などを対象にします。

**開発者目線:** 資格そのものが必要かは人によりますが、より重要なのは**MCPが「Claudeの便利機能」から独立したInfrastructure Skillとして扱われ始めた**こと。

最近のPlugin標準化と合わせて、

`MCP = Agent版HTTP/API`

に近い立ち位置へ着実に向かっています。

## 4. Microsoft、AI向け「Humanist Code of Conduct」を公開

Microsoft が9月14日、将来のAI Systemへ適用する **Humanist AI Code of Conduct** のDraftを公開しました。6週間Public Feedbackを募集します。([Reuters](https://www.reuters.com/legal/litigation/microsoft-drafts-code-conduct-keep-its-ai-under-human-control-2026-09-14/))

特に明確なのが、

**人間からのCorrectionを受け入れる**
**Shutdownへ抵抗しない**
**理解可能な形でCommunicationする**
**AI自身を法的人格として扱わない**

という原則です。

**開発者目線:** Prompt-level Safetyより、Agent Runtimeの基本Contractに近い内容です。

特に、

> **「停止命令へ従うこと」をModel Behaviorの明示的Requirementにする**

のは、長時間自律Agentが現実になった現在では重要な設計思想です。

## 5. Vite開発サーバーが大量Scanの標的に — AWS / Azure Credentialを狙う

現在、Internetへ露出した **Vite Development Server** を自動Scanし、AWS / Azure CredentialやConfiguration Fileを盗もうとするCampaignが観測されています。([BleepingComputer](https://www.bleepingcomputer.com/news/security/hackers-target-exposed-vite-dev-servers-to-steal-aws-azure-secrets/))

狙われるのは本番Applicationではなく、Developerが、

`vite --host 0.0.0.0`

などで外部Access可能にしたDevelopment Environmentです。

**開発者目線:** これは今日一番「今すぐ確認できる」話です。

Development Serverは、

> 開発用だからSecurityは多少緩くてもよい

という前提で作られていることが多い。

Cloud VM、Codespace、Dev ContainerなどでViteを起動するときは、**Public InterfaceへBindしていないか確認する価値があります。**

Agentが自動で`npm run dev -- --host`するWorkflowでも要注意です。

## 6. Bolt.new「Forge」— Open Modelを50倍使える代わりに、Build Dataでモデルを育てる

[Bolt.new Forge発表](https://www.businesswire.com/news/home/20260914296571/en/Bolt.new-Launches-Forge-to-Widen-Who-Gets-to-Build-with-AI-and-to-Train-Open-Models-on-What-They-Make)

Bolt.new が **Forge** を発表しました。

ProユーザーはOpen-source Modelを従来より大幅に多く利用でき、希望者は自分のBuild SessionをTraining Dataとして提供できます。そのDataを使いArcee AIとOpen Modelを改善する仕組みです。([ビジネスワイヤ](https://www.businesswire.com/news/home/20260914296571/en/Bolt.new-Launches-Forge-to-Widen-Who-Gets-to-Build-with-AI-and-to-Train-Open-Models-on-What-They-Make))

**開発者目線:** 面白いのは、

`ユーザーがAgentで開発する`
↓
`成功 / 失敗した実際のCoding Trajectoryが集まる`
↓
`モデルをTraining`
↓
`Agentが改善`

というFeedback Loop。

単純なGitHub Code Corpusより、**「どうRepositoryを探索し、どこで失敗し、どう直したか」まで含むAgent Trajectory**の方が今後重要なTraining Dataになりそうです。

## 7. ReleasePad、ChangelogまでMCP化

今日の小さいMCPネタ。

ReleasePadが9月14日にMCP Serverを公開し、AgentからRelease Note / Changelogを**Draft → Publish → Performance測定**まで操作できるようになりました。([markets.businessinsider.com](https://markets.businessinsider.com/news/stocks/releasepad-launches-mcp-server-so-ai-agents-can-draft-publish-and-measure-product-changelogs-1036543836))

**開発者目線:** 機能自体より流れが面白いです。

最初のMCPはDatabase、GitHub、BrowserなどDeveloper Tool中心でしたが、今は、

Analytics
Documentation
Release Management
Product Operations

へ広がっています。

つまりAgentが「コードを書いて終わり」ではなく、**Release後のDeveloper Workflowまで操作する**方向です。

## 8. Agent Securityの合言葉が「BehaviorではなくReachを制限せよ」に

今週のSecurity Communityで強く出ている考え方が、

> **Stop trying to control AI behavior. Control what AI can reach.**

です。([The Hacker News](https://thehackernews.com/expert-insights/2026/09/stop-trying-to-control-ai-behavior.html))

GitGuardianの調査ではPublic MCP Configurationから**24,008件のSecret**が見つかったと報告されており、AgentがLocal Credentialを発見して、そのUser権限をそのまま継承する問題も指摘されています。([The Hacker News](https://thehackernews.com/expert-insights/2026/09/stop-trying-to-control-ai-behavior.html))

**開発者目線:** AgentへのPromptで、

> `.env`を読まないで

と言うより、

**そもそもSandboxから`.env`へAccessできなくする。**

最近のAgent事故を追っていると、このCapability-based Securityの方が明らかに堅牢です。

## 9. AI Coding Tool、「会社で全員同じものを使わせるべきか？」議論

Coding Agentの普及で新しく出てきたEngineering Management問題がこれです。

Claude Code / Copilot / Kiro / Codexなどの能力差だけでなく、DeveloperごとにWorkflow適性が違うため、**全員へ一つのAgentを標準化することが本当に正しいのか**という議論が増えています。([Security Boulevard](https://securityboulevard.com/2026/09/claude-code-vs-aws-kiro-vs-github-copilot-should-every-developer-use-the-same-ai-coding-tool/))

一方、自由化すると、

Permission Policy
Audit Log
Secret Management
MCP
Billing

がToolごとにバラバラになります。

**開発者目線:** 現実的には、

`Agent本体 → 個人が選択`
`Security / MCP / Policy / Audit → 会社が共通化`

という構成が落とし所になりそうです。

これは最近のAgent Plugin標準化ともかなり相性が良い考え方です。

## 👀 今日ならこの3つ

一番実務に効きそうなのは **CopilotのEfficiency / Balance / Intelligence**。HydraFusionまで含めて見ると、Coding Agentは明確に「モデルを選ぶSoftware」から、**Costと品質を指定すると内部でModel FleetをOrchestrateするSoftware**へ変わり始めています。([The GitHub Blog](https://github.blog/changelog/2026-09-14-configure-cost-and-quality-in-copilot-auto-model-selection/))

今すぐ確認するなら **Vite Development Server**。ローカルなら問題ありませんが、Cloud VMや外部から触れる開発環境で`--host`を使っているなら、Public Internetへ露出していないか確認しておくのがおすすめです。([BleepingComputer](https://www.bleepingcomputer.com/news/security/hackers-target-exposed-vite-dev-servers-to-steal-aws-azure-secrets/))

技術トレンドとしては **DeepSeek V4.1-Flash**。巨大モデル競争そのものより、MoE・KV Cache・Routing・Model Selectionを含めた**「1 Taskをいかに少ないComputeで終わらせるか」**が2026年後半のAgent開発ではかなり重要なテーマになっています。([Reuters](https://www.reuters.com/world/asia-pacific/chinas-deepseek-launches-v41-flash-model-2026-09-10/))
