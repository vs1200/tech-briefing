## 1. GPT-6.1 Sol — Astra級へかなり近づき、価格はSol据え置き

[GPT-6.1 Sol公式モデルページ](https://developers.openai.com/api/docs/models/gpt-6.1-sol)

9月29日の OpenAI DevDay 2026 で、[OpenAI](https://openai.com/) が **GPT-6.1 Sol** を公開しました。

価格はGPT-6 Solと同じ **$2 / 1M input、$10 / 1M output**。一方でOpenAIは、Coding・Computer Use・Professional Workで上位のAstraへかなり近い性能になったとしています。Context Windowは**1.05M tokens、最大出力128K**です。([OpenAI Developers](https://developers.openai.com/api/docs/models/gpt-6.1-sol))

特にAPI Tool対応がかなり広く、

**Web Search / File Search / Code Interpreter / Hosted Shell / Apply Patch / Skills / Computer Use / MCP / Tool Search**

をResponses APIから利用できます。([OpenAI Developers](https://developers.openai.com/api/docs/models/gpt-6.1-sol))

**開発者目線:** 先週「SolをDefault、Astraを難問だけ」と書きましたが、6.1でその差がさらに縮まりました。

Coding Agentでは、

`GPT-6.1 Sol → default`
`Astra → 本当に難しいTaskへescalate`

という構成がかなり自然です。

なおOpenAI自身のBenchmark値なので、第三者評価はこれから見たいところです。

## 2. Codex Cloudに「Reusable Environment」— Cloud Agentの起動を毎回ゼロからやらない

[Codex更新の詳細](https://techcrunch.com/2026/09/29/openai-gives-codex-reusable-cloud-environments-that-work-across-devices/)

CodexのCloud実行環境がかなり改善されました。

これまでCloud Taskは毎回独立したSandboxを作る性格が強かったのに対し、今後は**Reusable Development Environment**を作れます。Teamで同じEnvironment Configuration、Permission、Settingを共有することも可能です。([TechCrunch](https://techcrunch.com/2026/09/29/openai-gives-codex-reusable-cloud-environments-that-work-across-devices/))

つまり、

```text
repo
+ dependencies
+ environment
+ permissions
+ settings
        ↓
Reusable Codex Environment
        ↓
task A / task B / task C
```

となります。

**開発者目線:** Cloud Coding Agentで地味に大きかった、

> Agent起動 → npm install / build environment構築 → ようやく仕事

というSetup Costを減らせます。

Dev Containerに近い発想が**Agent Runtime側へ標準装備**されてきました。

## 3. Codex CLI刷新 — Voiceで指示、複数Agentを`/agents`で管理

同じCodexですが、CLI側もかなり変わっています。

新しいCLIではVoiceからTaskを開始・修正可能になり、**`/agents` Viewで複数のAgent Taskをまとめて確認**できます。Worktree、Session Resume、Prompt Editingも改善されました。([TechCrunch](https://techcrunch.com/2026/09/29/openai-gives-codex-reusable-cloud-environments-that-work-across-devices/))

ちょうど9月29日の`rust-v0.159.0`では、実行中のResponseをInterruptして途中から指示を変えるSteeringも改善されています。([Havoptic](https://www.havoptic.com/))

**開発者目線:** Coding Agent UIが、

`prompt → 待つ → answer`

から、

```text
task A ─ running
task B ─ waiting
task C ─ running
       ↑
  人間が途中介入
```

という**Process Manager**へ変わっています。

tmux的なAgent UXに近づいているのが面白いところです。

## 4. Codex Security Cloud — Repositoryを常時スキャンして修正まで作る

DevDayでは **Codex Security Cloud** も大きく拡張されました。

GitHub Repository全体を、

**On-demand / Scheduled / New commitごと**

にScanし、Findingを単に列挙するだけでなく、重複除去、Reachability確認、Evidence収集、修正Patch生成までCloud上で行います。Laptopを閉じていても継続します。([TechCrunch](https://techcrunch.com/2026/09/29/openai-gives-codex-reusable-cloud-environments-that-work-across-devices/))

OpenAIによると、研究Preview開始以降に**3万以上のCodebase・3,000万以上のCommit**をScanしています。([OpenAI](https://openai.com/index/daybreak-securing-the-world/))

**開発者目線:** Security Scannerが、

`static rule → warning`

ではなく、

`finding → investigate → reproduce → patch → verify`

という**Security Engineer Agent**になっています。

先週紹介したGitHubのAgentic Autofixとも完全に同じ方向です。

## 5. Decisions API — 「Agentの判断だけ」ならGPT-6 Lunaへ

DevDayで個人的にかなり気になるのが **Decisions API** です。

GPT-6 Lunaを使い、

**Classification / Ranking / Routing / Single-step Decision**

のような「文章を長く生成する必要のない判断」を低Latency・低Costで行うAPIとして発表されました。([The Decoder](https://the-decoder.com/openai-expands-codex-and-its-api-at-devday-with-security-scans-a-decisions-api-and-ultrafast/))

これはこの数日紹介した、

**Jev**
**CLM-8B**
**Julia 1**

とまったく同じ問題意識です。

**開発者目線:** ここ最近かなり明確なTrendになりました。

```text
難しいreasoning
      ↓
frontier model

routing / classify / approve
      ↓
small decision model

deterministic処理
      ↓
ordinary code
```

**「Agent Loopの全StepをLLM生成で処理しない」**設計が2027年の定石になりそうです。

## 6. Agents APIにComputer Use — GUI操作がFirst-class Toolへ

DevDayではAgents APIにも**Computer Use**が追加されました。([The Decoder](https://the-decoder.com/openai-expands-codex-and-its-api-at-devday-with-security-scans-a-decisions-api-and-ultrafast/))

AgentがBrowserだけでなくGUI Applicationを認識し、Mouse / Keyboard相当のActionを行うWorkflowをAPIから組めます。

GPT-6.1 Sol自体もComputer Use Toolを正式サポートしています。([OpenAI Developers](https://developers.openai.com/api/docs/models/gpt-6.1-sol))

**開発者目線:** MCP/APIがあるApplicationなら当然そちらを使うべきですが、世の中にはAPIが存在しないSoftwareが大量にあります。

AgentのTool Hierarchyは、

```text
1. deterministic API
2. MCP
3. shell / code
4. Computer Use
```

くらいに考えるのが良さそうです。

Computer Useは万能Toolというより、**最後の互換Layer**として非常に強力です。

の総合戦になっています。

SonnetをCodex Harnessで使う、GPTを別Harnessで使う、といった比較も増えていきそうです。

## 8. Godot + Conan — GDExtensionのC++依存管理を普通のPackage Managementへ

AI以外から面白い小ネタです。

Conan Teamが、Godot Engine の **GDExtension + C++** でConanを使うWorkflowを公開しました。([TechNewsReel](https://technewsreel.com/software-and-development/conan-automates-c-library-integration-for-godot-via-gdextension))

`godot-cpp`自体とFlecsのようなNative LibraryをConanで解決し、CMakeからBuild。そのままGDExtensionとしてGodotへ読み込みます。([TechNewsReel](https://technewsreel.com/software-and-development/conan-automates-c-library-integration-for-godot-via-gdextension))

つまり、

```text
conanfile
   ↓
godot-cpp
flecs
other C++ libs
   ↓
CMake
   ↓
GDExtension
```

です。

**ゲーム開発目線:** UnityのUPMほどEngine統合されたNative Dependency Managementを持たないGodot C++では、こういう一般的なC++ Ecosystemへ乗れるのは大きいです。

「Game Engine専用のDependency System」ではなく、**通常のNative Development Toolchainを再利用する**方向として良い事例です。

## 9. Firefox 157 — 数年ぶりの大型UI Refresh、Compact Modeも復活

[Firefox 157公式Release Notes](https://www.firefox.com/en-US/firefox/157.0/releasenotes/)

Mozilla Firefox **157** が9月29日に正式リリースされました。

Project Novaとして開発されていた新Design SystemがDefaultとなり、Toolbar / Sidebar / Menu / Tabsなどが全面刷新されています。さらに**Compact Modeが正式に復活**し、小さい画面やSplit Viewで表示領域を広く取れます。([Firefox](https://www.firefox.com/en-US/firefox/157.0/releasenotes/))

**開発者目線:** 技術革新というよりDeveloper UX枠ですが、Browser Devをする人には毎日触るToolです。

最近のApplicationが「余白を大きくする」方向へ行く中で、Power User向けに**Information Densityを選択可能に戻した**のは歓迎されそうです。

## 10. MATLAB / Simulink R2026b — AIより「巨大Systemをどう管理するか」

MATLAB / Simulink **R2026b** も9月29日に公開されました。

新しい **Simulink Variant Manager、Visual Inspection Toolbox、Polyspace Test Server** が追加され、Aerospace、Embedded、Perception、AI、Audioなども更新されています。([DailyCADCAM](https://dailycadcam.com/mathworks-launches-matlab-simulink-r2026b/))

特にVariant Managerは、同じSystemから、

`vehicle A`
`vehicle B`
`hardware revision C`

のような多数のConfigurationを管理する用途です。

**開発者目線:** ゲーム開発でも意外と似た問題があります。

Mobile / Console / Region / Feature Flag / SKU差分を、

`if platform == ...`

で増殖させると破綻します。

**Variantを明示的なConfigurationとしてModel化する**考え方は、大規模Unity Projectでも参考になります。

## 👀 今日ならこの3つ

今日はまず **GPT-6.1 Sol**。GPT-6 Sol公開からわずか1週間で6.1になり、価格据え置きでAstraとの差をかなり詰めてきました。1M Contextに加えてHosted Shell / Apply Patch / Skills / Computer Use / MCPまで一つのModel APIへ揃ったので、Agentを組むDefault Modelとしてかなり強い位置です。([OpenAI Developers](https://developers.openai.com/api/docs/models/gpt-6.1-sol))

Coding Agentを実際に多用するなら **Reusable Codex Environment + `/agents`** も注目です。Coding Agentが「Terminalで一匹動かすCLI」から、**複数のRemote WorkerをLocal/Phone/Cloudから操るDevelopment Infrastructure**へ変わってきています。([TechCrunch](https://techcrunch.com/2026/09/29/openai-gives-codex-reusable-cloud-environments-that-work-across-devices/))
