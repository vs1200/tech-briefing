今朝は **「Agentがコードを書く」から「Agentに現実のシステムを安全に触らせる」へ**という流れが目立ちます。8月28日に出た話を中心に、昨日までの重複はなるべく避けました。

---

## 1. Anthropic「MHS」— AI Agentがロボットや実験機器を直接操作

Anthropic が **Model Hardware Standard（MHS）** のResearch Previewを公開しました。Agentから顕微鏡、ロボットアーム、量子コンピュータのレーザー制御など、プログラム可能な物理機器を操作するための共通Frameworkです。([reuters.com](https://www.reuters.com/technology/anthropic-unveils-new-framework-allowing-ai-agents-operate-physical-devices-2026-08-27/))

イメージとしては、

**MCP → ソフトウェア・データ**
**MHS → 物理デバイス**

に近いです。まだPartnerとのSafety Evaluation段階で、後にOSS化する予定とされています。

**開発者目線:** AgentのTool Callingがついに「PCの中」から外へ出始めています。ロボティクスだけでなく、将来的には自動テスト端末やIoT機器にもつながり得る設計で、今日いちばん気になる話です。

---

## 2. Claude Code 2.1.251 — モデル切替までHookで制御可能に

[Claude Codeのリリース追跡](https://www.havoptic.com/)

8月28日の Claude Code v2.1.251では、**モデル切替に反応できる新しいHook Event**などが追加されています。また、Remote Control側からSubagentのTool実行状況をリアルタイムに確認できる改善も入っています。([Havoptic](https://www.havoptic.com/))

前日の2.1.248では、危険な操作を制限するRestricted ModeやPrompt Cache周辺も追加されていました。

**開発者目線:** Hookでモデル切替まで観測・制御できるようになると、「通常作業は安いモデル、設計や難問だけOpus級」のような**組織独自のAgent Policy**を作りやすくなります。

---

## 3. JFrog「Traffic Controller」— AI Agentの`npm install`まで統制する

JFrog が **Traffic Controller** を発表しました。

面白いのは、人間だけでなく**AI AgentによるPackage DownloadもGovernance対象**にしていること。Package RequestをNetwork Layerで捕捉し、組織が許可したRepositoryやPolicyへRoutingします。([TNGlobal](https://technode.global/2026/08/28/jfrog-traffic-controller-software-package-downloads-ai-agents/))

Agentが勝手に、

`npm install xxx`
`pip install xxx`
`cargo add xxx`

する世界では、Package Manager自体がAgentのToolになります。

**開発者目線:** Agent権限管理の次に来るのが**Software Supply Chain管理**という流れはかなり自然です。

## 4. Pydantic AI × You.com — Web SearchをAgentの1行Toolへ

You.com とPydantic AIが、YouSearch / YouResearchを **Pydantic AI HarnessのNative Capability** として提供すると8月28日に発表しました。([Futurum](https://futurumgroup.com/insights/youcom-turns-real-time-web-search-into-a-one-line-agent-capability/))

つまりAgent Framework側で、リアルタイムWeb検索やResearchをかなり簡単にToolとして組み込めます。

**開発者目線:** Agentを自作すると、

`LLM + Search + Browser + Memory + Sandbox`

を毎回組み合わせる必要がありますが、こうした機能がFramework標準部品へ吸収されつつあります。

## 5. Huawei、16 Agent構成の「CodeArts Agent」をアジア太平洋で正式提供

[Huawei CodeArts Agent発表](https://www.prnewswire.com/apac/news-releases/huawei-cloud-codearts-agent-now-available-across-asia-pacific-bringing-agentic-ai-to-software-development-302862642.html)

Huawei が8月28日、CodeArts AgentをPublic BetaからGAへ移行しました。

面白いのは単一Coding Agentではなく、**要件分析・Architecture・Coding・Test・Issue解決・Reviewなどを担当する16種類のAgent Team**を持つこと。30以上の再利用可能なEngineering Skillも組み込んでいます。([PR Newswire](https://www.prnewswire.com/apac/news-releases/huawei-cloud-codearts-agent-now-available-across-asia-pacific-bringing-agentic-ai-to-software-development-302862642.html))

**開発者目線:** Claude CodeのSubagentやKiro Crewなども含め、Coding Agent競争が「一人の万能Agent」から**専門Agent Team**へ動いています。

## 6. Tencent、Gamescomでゲーム開発向けAI Tool群を展示

Tencent Games Central TechがGamescom 2026で、ゲーム制作向けのAI・Technology Tool群をまとめて展示しています。([Pocket Gamer](https://www.pocketgamer.biz/tencent-games-showcases-ai-tools-for-game-development-at-gamescom/))

ゲーム業界では生成画像そのものよりも、Production Pipelineや開発効率化へAIを組み込む動きがかなり強くなっています。

Unityの2026 Game Development Reportでも、AI利用はCoding Assistanceが62%で最多、調査対象の**50%がMCP Serverを利用**していると報告されています。([Unity](https://unity.com/blog/2026-unity-game-development-report-trends))

**ゲーム開発目線:** 「AIでAssetを作るか」より、**Editor・Build・QA・Production ManagementをAgentから触れるようにする**領域の方が今は面白いです。

## 7. AWS「Continuous Modernization Pipeline」— Agentを巨大リファクタリングへ投入

[AWSの技術記事](https://aws.amazon.com/blogs/devops//)

Amazon Web Services が8月28日、AWS Transformを使った **Continuous Modernization Pipeline** の構築方法を公開しました。([Amazon Web Services, Inc.](https://aws.amazon.com/blogs/devops//))

考え方はかなり面白く、

**AIでコード生成速度が上がったなら、古いコードを一度だけ移行するのではなく、Modernization自体を継続Pipelineにする**

というもの。

**開発者目線:** 以前紹介した「AsanaがCodexで巨大なTest Migrationを処理した」話ともつながります。Agentの有力用途として、**Technical Debt返済**がかなり確立してきました。

## 8. 地味に便利そう：「skills-manager」が伸びている

今日のOSS小ネタ。

**skills-manager**というRust製Desktop Appが公開されており、Claude Code、Codex、Cursor、Copilot、Gemini CLIなど**50以上のCoding Tool間でAgent Skillを管理・同期**することを狙っています。8月28日時点で4,000 Stars超と報告されています。([The Infinity](https://theinfinity.dev/tools/skills-manager))

これはかなり今っぽい問題で、

`~/.claude/...`
`.github/...`
`.agents/...`
`Cursor用設定`

などに同じKnowledgeをコピーしたくない、という需要への回答です。

**開発者目線:** Agent Pluginsの標準化が進めば不要になる部分もありそうですが、**「AgentごとにSkillをどう共有するか」問題がOSSのテーマになっている**こと自体が興味深いです。

## 9. さらに小ネタ：「hunk」— Agent時代のDiff Viewer

もう一つOSS。

**hunk**は「review-first terminal diff viewer for agentic coders」を掲げるTerminal Toolで、8月26日にv0.20.0が出ています。GitだけでなくJujutsuやSaplingも意識した設計で、8月28日時点で約8,900 Starsと報告されています。([The Infinity](https://theinfinity.dev/tools/hunk))

Agentが大量にコードを書くと、

**書く速度 >>> 人間が読む速度**

になります。

そこでEditorではなく、**AIが作った変更を高速にレビューするUI**そのものがDeveloper Toolの新カテゴリーになりつつあります。

これはかなり追いたい流れです。

## 10. AI Data Center、電力だけでなく「水使用量」も問題に

NEXTDC が8月28日に発表した数字では、設備拡大に伴い電力だけでなく水使用効率も悪化。WUEは2.25 → **2.40 L/kWh**、PUEも1.44 → **1.49**となりました。([reuters.com](https://www.reuters.com/business/energy/australia-data-centre-firm-nextdc-reports-rising-water-energy-use-with-profit-2026-08-28/))

AI Data Center拡大を受け、オーストラリアでは新設Data Centerに再生可能電力開発を要求する案なども議論されています。

**開発者目線:** LLMのCostを「$/1M tokens」だけで考えがちですが、Inferenceが巨大化すると、電力・冷却水・半導体供給までSoftware Architectureの裏側に存在します。

Local SLMやModel Routingが注目される理由も、単なるAPI料金だけではありません。

## 👀 今日ならこの3つ

今日は **Anthropic MHS** が一番面白いです。MCPによって「AgentからSoftwareを触る」ことが普通になり、次は**Agentから現実世界を触るためのInterface**が標準化対象になり始めています。([reuters.com](https://www.reuters.com/technology/anthropic-unveils-new-framework-allowing-ai-agents-operate-physical-devices-2026-08-27/))

実務寄りでは **JFrog Traffic Controller**。AgentにShellを渡した後に「勝手にPackageを追加する問題」が出てくるのは当然で、Coding Agent向けSecurityが **Permission → Sandbox → Supply Chain** と一段ずつ深くなっているのが見えます。([TNGlobal](https://technode.global/2026/08/28/jfrog-traffic-controller-software-package-downloads-ai-agents/))

そして小ネタでは **skills-manager + hunk**。最近のOSSを見ると、Agentそのものを作るToolだけでなく、**Agentを管理する・Skillを共有する・Agentの変更を人間がレビューする**ためのDeveloper Toolが急速に増えています。この周辺はしばらく重点的に拾う価値がありそうです。
