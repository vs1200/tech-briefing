今日はかなり面白いです。特に **GitHub Copilotがデスクトップアプリそのものを操作可能に、Decision Model競争がわずか数週間でAWS・Cloudflareまで拡大、FMODがBose傘下へ** が大きめ。昨日扱ったHydraFusion、PixelLeak、Unity External Dependency Managerなどは外しました。

## 1. GitHub Copilot、ついにデスクトップアプリを直接操作

[GitHub公式：Computer use in Copilot](https://github.blog/changelog/2026-10-01-github-copilot-can-now-interact-with-desktop-apps/)

[GitHub](https://github.com/) が10月1日、Copilot CLI / Copilot Appに **Computer Use** をPublic Previewで追加しました。

macOS / Windows上で、

**画面内容を読む → Buttonを押す → Text入力 → Scroll → Drag → 別Applicationへ移動**

までAgentが実行できます。GitHub自身のDemoではSafari上の経費精算Workflowを操作しています。API・CLI・MCPが存在しないLegacy Softwareも対象です。操作開始時にはApprovalが必要で、組織側から無効化もできます。([The GitHub Blog](https://github.blog/changelog/2026-10-01-github-copilot-can-now-interact-with-desktop-apps/))

**開発者目線:** Coding Agentの境界がIDEから完全に外へ出ました。

```text
Code / shell / MCP
        ↓
     Copilot
        ↓
macOS / Windows GUI
```

例えばUnity Editor、社内Build Tool、Spreadsheet、Browser上のAdmin Toolなども理論上は同じAgent Workflowへ組み込めます。

ただしComputer Useは不安定になりやすいので、**API → MCP → CLI → GUI操作**くらいの優先順位にするのがよさそうです。

## 2. Cloudflare Clef — Decision Model競争が一気に本格化

[Cloudflare公式：Introducing Clef](https://blog.cloudflare.com/clef-decision-models/)

[Cloudflare](https://www.cloudflare.com/) が **Clef / Clef-flash** をApache 2.0でOpen Source公開しました。

これはChatbotではなく、

`state + choices → probabilities`

を返す**Decision Model**です。

ClefはQwen3.8-27B、Clef-flashはQwen3.5-9BをBackboneにし、通常のAutoregressive生成を行わず、候補を並列Scoreします。Vision入力と64K Contextにも対応します。([Cloudflare Blog](https://blog.cloudflare.com/clef-decision-models/))

Cloudflare公称ではMedian Latencyが、

**Clef-flash：38.8ms**
**Clef：209ms**
**Jev：524ms**

でした。BenchmarkによってJevが勝つものもあり、完全な上位互換ではありません。([Cloudflare Blog](https://blog.cloudflare.com/clef-decision-models/))

**開発者目線:** このDaily Briefingでここ2週間追ってきた流れが急速に本流化しています。

`Frontier LLM → 何でも判断`

ではなく、

**`Frontier LLM → reasoning`**
**`Decision Model → routing / classification / approval`**
**`ordinary code → deterministic processing`**

へ分ける設計です。

## 3. AWSもStrands Decider 2B — わずか2BをローカルでAgentの「判断役」に

[Strands公式：Introducing Strands Decider 2B](https://strandsagents.com/blog/introducing-strands-decider/)

ほぼ同じ日にAWSのStrands Teamも **Strands Decider 2B** をOpen Source公開しました。

Jevに触発されて作られたModelで、約2B Parameters。自由文を生成せず、あらかじめ与えられた候補から選び**Confidence Score**を返します。Local実行を強く意識したサイズです。([Strands Agents](https://strandsagents.com/blog/introducing-strands-decider/))

例えば、

```text
"DB migration failed"

retry       0.04
rollback    0.87
ignore      0.01
ask-human   0.08
```

のような使い方です。

**開発者目線:** これはかなり明確なSignalです。

この数週間だけで、

**Jev → CLM → Julia → OpenAI Decisions → Clef → Strands Decider**

まで出てきました。

Decision Modelは一過性の小ネタではなく、**Agent Architectureの新しいModel Layer**として定着する可能性が高くなってきました。

## 4. VS Code、Agentが「PRをMergeするところ」まで担当

[GitHub公式：VS Code September Agent releases](https://github.blog/changelog/2026-10-01-github-copilot-in-vs-code-september-2026-releases/)

9月分のVS Code / Copilot更新まとめが10月1日に公開されました。

特に面白いのが **Agent Merge**。

Agentが実装した後、

**Review Feedback対応**
**Failed Check修正**
**Merge Conflict解消**
**Workflow再実行**

まで処理し、PRをMerge可能な状態へ持っていきます。([The GitHub Blog](https://github.blog/changelog/2026-10-01-github-copilot-in-vs-code-september-2026-releases/))

さらにAgents WindowからCopilot / Claude / Codex Sessionを直接PR化したり、Agent Taskをhourly / daily / weeklyで定期実行したりできます。Dev Container内でAgent Sessionを起動する機能も追加されています。([The GitHub Blog](https://github.blog/changelog/2026-10-01-github-copilot-in-vs-code-september-2026-releases/))

**開発者目線:** IDEが、

`edit → build → commit`

のToolから、

**`Agent Fleet + CI/CD Workflow Console`**

へ変わりつつあります。

特に「Reviewを受けてからMerge可能になるまで」は人間の細かいContext Switchが多いので、自動化効果が大きそうです。

## 5. Cloudflare AI Search正式版 — PDFのOCRと画像Embeddingまで一つのRAG Pipelineに

[Cloudflare公式：AI Search GA](https://blog.cloudflare.com/ai-search-ga/)

Cloudflareの **AI Search** がGeneral Availabilityになりました。

Workers AI + Vectorize + R2 + Browser RunをまとめたManaged Retrieval Pipelineで、新版ではTextだけでなく、

**Native image embeddings**
**PDF OCR**
**最大10MiBのFile**
**Multimodal Retrieval**

へ対応しました。([Cloudflare Blog](https://blog.cloudflare.com/ai-search-ga/))

特定LLMには依存せず、検索結果を好きなChat Modelへ渡せます。

**開発者目線:** RAGを作るときに面倒なのはEmbedding APIではなく、

`crawl → parse → OCR → chunk → embed → index → update`

のPipelineです。

そこをManaged Serviceへ丸ごと寄せる製品が成熟してきました。

社内Documentation検索のような用途なら、Vector DBから全部自作する理由はかなり減っています。

## 8. Rust 1.99 — C Variadic FunctionをRust側で定義可能に

[Rust公式：Rust 1.99.0](https://blog.rust-lang.org/2026/10/01/Rust-1.99.0/)

Rust **1.99.0** が10月1日にStableになりました。

大きい変更は **C ABI Variadic Functionの定義**。

これまでもRustから`printf`のようなC Variadic Functionを**呼ぶ**ことはできましたが、1.99からRust側で、

`unsafe extern "C" fn foo(mut args: ...)`

を定義できます。`VaList`もStable化されています。([Rust Blog](https://blog.rust-lang.org/2026/10/01/Rust-1.99.0/))

Raw Pointerからsize / alignmentを取得するAPIや`Vec::into_parts`などもStable化されています。

**開発者目線:** 普通のApplicationでは地味ですが、FFI / Runtime / Embedded / Game Middlewareを書く人には重要です。

Rustが「安全なApplication Language」だけでなく、**C/C++と境界を共有するSystem Language**として穴を少しずつ埋めています。

次はついに **Rust 1.100** です。

## 9. IBM Bob、Coding Agentを完全Air-gap環境でも実行可能に

[IBM Bob self-hostedの詳細](https://devops.com/ibm-moves-its-bob-coding-agent-inside-the-firewall/)

[IBM](https://www.ibm.com/) のCoding Agent **Bob** がSelf-hosted Deploymentへ対応しました。

On-premise / Private Cloud / Sovereign Cloudだけでなく、**Internetへ一切接続しないAir-gapped Environment**でも動かせます。([DevOps.com](https://devops.com/ibm-moves-its-bob-coding-agent-inside-the-firewall/))

Bob自体はPlanning → Coding → Test → Deployment / Modernizationまで複数Agentで処理し、Claude / Mistral / IBM GraniteなどをTaskに応じてRoutingします。IBMによると社内では8万人以上が利用しています。([DevOps.com](https://devops.com/ibm-moves-its-bob-coding-agent-inside-the-firewall/))

**開発者目線:** Coding AgentはRepository全体・CI・Credentialへ強い権限を持つため、金融・政府・大企業ではCloud Agent自体が採用できないケースがあります。

そこで、

> **CodeをAIへ送るのではなく、AIをCodeの場所へ持ってくる**

という方向。

Local LLMの性能が上がるほど、この構成も現実的になります。

## 10. Cloudflare Workers KV Instant — 世界300拠点へ250msで反映

[Cloudflare公式：Workers KV Instant](https://blog.cloudflare.com/workers-kv-instant/)

最後はAIではないInfrastructure小ネタ。

Cloudflareが社内で長年使ってきたDistributed KV System **Quicksilver** を、Workers KVの新Mode **KV Instant** としてDeveloperへ開放しました。

Cloudflare公称で、

**read p99 < 2ms**
**global replication ≈ 250ms**

です。従来KVにあったCold-read Penaltyもなくなります。([Cloudflare Blog](https://blog.cloudflare.com/workers-kv-instant/))

APIは既存Workers KVとほぼ同じ。

**開発者目線:** Edge Config、Feature Flag、Routing Rule、Agent Policyのような、

> **writeは少ないが世界中から非常に頻繁に読むData**

に向いています。

Agent Infrastructureでも「このToolは許可する」「このModelへRouteする」といったPolicyをGlobal Edgeへ高速配布する用途と相性が良さそうです。
