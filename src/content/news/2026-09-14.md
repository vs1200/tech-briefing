週末明けなので巨大な新モデル発表は少なめですが、**Coding Agentを「使う」段階から「評価・テスト・運用する」段階への移行**がかなり鮮明です。特にClaude CodeのPlugin Evals、Real-SWE、PydanticAIのCapabilitiesは今後のAgent開発に効きそうです。昨日まで扱ったAgents API、CopilotのAgent Ensemble、RubyGems事件などは外しました。

---

## 1. Claude Code「Plugin Evals」— Skill / Pluginにも回帰テストを書く時代へ

Claude Code v2.1.269で、新しい **`claude plugin eval`** が追加されました。Pluginに対してテストケースを実行し、結果を採点してJSON / HTML Reportとして出力できます。PluginなしのBaselineとの比較も可能です。([The AI Toolchain](https://aitoolchain.io/newsletter/tail/24/))

同じ更新ではVS Code側にAgent Map、Hooks Dialog、Permission Rules Dialog、SubagentのLive Progressなども追加されています。([The AI Toolchain](https://aitoolchain.io/newsletter/tail/24/))

**開発者目線:** これはかなり重要です。今までSkillや`CLAUDE.md`は、

> Promptを変えた → なんとなく良くなった気がする

になりがちでした。

今後は、

`Skill変更 → Eval Suite → Baseline比較 → CI → Release`

という**普通のSoftware Engineeringと同じ回帰テスト**をAgent Behaviorにも適用できます。

Skillを自作している開発者には、特にチェックする価値があります。

---

## 2. Real-SWE — 「公開Repoでは強いAgent」が社内コードではかなり苦戦

[Specific Labs：Real-SWE](https://www.ycombinator.com/companies/specific-labs)

Specific Labsが **Real-SWE** という新しいCoding Agent Benchmarkを公開し、週末にHacker Newsなどで話題になっています。

従来のSWE-benchなどと違い、**モデルがTrainingで見ていないPrivate Enterprise Codebase**から実際の開発Taskを作っています。例えば20万人超のユーザーを持つApplicationや、10万件超の銀行Statementを処理するFintech Systemなどです。([Y Combinator](https://www.ycombinator.com/companies/specific-labs))

公開されている初期結果では、最上位モデルでもPass Rateが4割未満。つまり未知のCodebaseでBusiness Ruleまで読み解くTaskは、公開Benchmarkよりかなり難しいようです。([Coincamps](https://coincamps.ai/flash/e366607))

**開発者目線:** 個人的にはかなり良いBenchmarkだと思います。

実務Coding Agentで重要なのはLeetCodeではなく、

`知らない巨大Repoを読む`
→ `暗黙の設計を理解する`
→ `既存Patternに合わせる`
→ `複数Fileを変更する`

能力だからです。

**「SWE-bench 90%だからEngineer代替」みたいな議論への良いReality Check**になりそうです。

## 3. PydanticAI「Capabilities」— Skill + Tool + Hook + Model設定を一つの部品へ

9月12日の PydanticAI 更新で、新しい **`capabilities`** Extension Systemが入りました。

一つのCapabilityに、

`Tools`
`Hooks`
`Instructions`
`Model settings`

をまとめ、Agent間で再利用できます。さらにSearch、Sandbox Execution、Memory、Guardrail、Durable ExecutionなどのBuilt-in Capabilityも用意されています。([The AI Toolchain](https://aitoolchain.io/newsletter/tail/24/))

**開発者目線:** 昨日まで紹介してきたAgent Plugin / Skillの流れとかなり近いです。

これまで、

```text
Agent
 ├ prompt
 ├ tools
 ├ hooks
 ├ memory
 └ model config
```

を毎回組み立てていたのを、

```text
Agent
 └ capabilities: [coding, web, memory, sandbox]
```

のような**再利用可能なAgent Component**へする。

Agent Framework側でも「AgentのPackage化」が始まっています。

## 4. Agentの会話履歴からAPI Keyを探す「FailproofAI」

今日の小さいけれど実用的なSecurity Tool。

**FailproofAI 1.0.4** が9月12日に公開され、Claude CodeなどAgentのTranscriptをLocal Scanして**Credential漏洩を検出**できるようになりました。OpenClawのSQLiteにもNative対応しています。([The AI Toolchain](https://aitoolchain.io/newsletter/tail/24/))

普通のSecret Scannerは、

`Repository → API_KEY発見`

ですが、これは、

`Agent Transcript → API_KEY発見`

です。

**開発者目線:** Agentが、

> `cat ~/.config/foo/credentials`

を実行して、その結果を会話Contextへ載せた場合、**Gitには一切残らないのにLLM TranscriptにはSecretが残る**可能性があります。

Agent時代にはRepositoryだけでなく、**Conversation / Trace自体もSecurity Scan対象**になるという分かりやすい例です。

## 5. Codex CLI、Linux / WindowsにもVoice + Thread単位Instruction

Codex CLI の9月11日更新では、Voice SupportがLinux / Windows TerminalにもBundledされました。

同時に**Thread-scoped Instructions**も追加されています。([The AI Toolchain](https://aitoolchain.io/newsletter/tail/24/))

後者は地味ですが、Repository全体の`AGENTS.md`を変えず、

> このSessionだけはPerformance改善を優先

のような一時的な指示をThreadへ持たせやすくなります。

**開発者目線:** Coding AgentのInstructionも、

`Global`
`→ User`
`→ Repository`
`→ Directory`
`→ Session / Thread`

という**Scope Hierarchy**を持つ方向へ成熟しています。

## 6. NVIDIA Transformer Engine 2.19 — 早くもRubin対応

NVIDIA の **Transformer Engine 2.19** が9月11日に公開され、次世代 **Rubin GPU** 対応が入りました。

さらにExperimentalなHybrid Quantization、2D MXFP8 Block Scaling、GatedDeltaNetAttention Kernel、Context Parallelism拡張なども含まれます。([The AI Toolchain](https://aitoolchain.io/newsletter/tail/24/))

**開発者目線:** Rubin Hardwareそのものより、Software Stackが既に対応し始めている点が重要です。

NVIDIAは新GPUを出してからLibraryを対応させるのではなく、

`CUDA / Transformer Engine / NCCL / Framework`
↓
`Hardware`

をほぼ同時に使えるようにするSoftware Moatを維持しています。

AI Infrastructureを追うならHardware SpecよりこのLayerを見る方が面白いです。

## 7. Godot 4.8 dev 5 — 待望のTexture Streaming

ゲーム開発枠では Godot Engine **4.8 dev 5** が9月10日に公開されています。4.8は今月後半にFeature Freeze予定なので、最後期のDevelopment Snapshotです。([Godot Engine](https://godotengine.org/article/dev-snapshot-godot-4-8-dev-5/))

特に大きいのが、長年要望されていた**Mip-level Texture Streaming**。

Cameraから遠いTextureは低解像度MipだけをMemoryへ載せ、必要になったら高解像度を読み込みます。([Cyborgs](https://cyborgs.pro/fr/blog/godot-4-8-dev-5-brings-mip-level-texture-streaming/))

**Unity開発者目線:** Unityでは馴染み深い仕組みですが、Godotにとっては大型3D GameでのVRAM使用量を改善する重要なPieceです。

GodotがIndie 2D Engineから、**より大規模な3D Productionを扱えるEngineへ地道に穴を埋めている**のが分かる更新です。

## 8. LM Studio 0.4.24 — llama.cppの細かいLoading Optionを直接Override

LM Studio **0.4.24** が9月12日に公開されました。

GGUFを読み込む際、Engine Protocolから**高度なllama.cpp Argument Override**を指定できるようになっています。またDrafter ModelのCompatibility判定も改善されました。([The AI Toolchain](https://aitoolchain.io/newsletter/tail/24/))

**開発者目線:** Local LLMを普通にChatするだけなら不要ですが、

`KV cache`
`GPU offload`
`Context / Memory関連`
`特殊なllama.cpp設定`

まで触りたいPower Userには、LM Studioを捨てて直接llama.cppを使う必要が減っていきます。

メモリの限られたMacでLocal Modelを試す場合にも地味に嬉しい方向性です。

## 9. Rune — 「Unix Soul」なKeyboard-first IDEがGPLv3でOSS化

[Rune公式](https://rune.build/)

週末のDeveloper Communityで面白かったのが **Rune**。

macOS / Linux向けのGPU-rendered IDEで、

**Keyboard-driven UI + Terminal Multiplexer + Debugger + Language Intelligence + Agent**

を一つにまとめています。Go / Python / Rustを特に強くサポートしています。([Rune](https://rune.build/))

そして9月13日、Codebaseを**GPLv3でOpen Source化**したことが話題になっています。([Linuxiac](https://linuxiac.com/rune-keyboard-driven-ide-is-now-open-source-under-gplv3/))

**開発者目線:** VS CodeのExtension文化とはかなり逆で、

> 「CLI Toolは既にPlugin Systemなのだから、IDEがUnixへ寄ればよい」

という思想。

Ghostty + tmux + Neovim的なWorkflowが好きなら、思想としてかなり面白いIDEです。

## 10. Agent Evalsが「専門Tool」ではなくDeveloper Workflowへ入り始めた

最後は今週末の複数Releaseから見えるトレンド。

Claude Codeだけでなく、Braintrustも**Claude Code / Codex / OpenCodeなど7種類のCoding AgentをTrace対象**にし、LangSmithもCLIからLLM-as-Judgeを作成してExperiment比較できるようになっています。([The AI Toolchain](https://aitoolchain.io/newsletter/tail/24/))

つまりAgent開発が、

```text
2025
Promptを書く
↓
なんとなく試す
```

から、

```text
2026
Agent / Skillを変更
↓
Trace
↓
Eval
↓
Baseline比較
↓
Regression検出
↓
CI
```

へ移っています。

**開発者目線:** これは今日のニュース全体で一番大きな流れかもしれません。

Coding Agentを「便利なAI Tool」として使うだけなら不要ですが、**会社独自のSkill / Hook / MCP / Agent Workflowを育てるなら、そろそろEvalをTest Codeと同じ一級Artifactとして扱う段階**に来ています。

## 👀 今日ならこの3つ

一番試したいのは **`claude plugin eval`**。Skillを改善しても「本当に良くなったのか」を定量的に判断しづらかった問題へ、Anthropic自身がTesting Workflowを用意したのはかなり大きいです。([The AI Toolchain](https://aitoolchain.io/newsletter/tail/24/))

次は **Real-SWE**。公開Repository Benchmarkでは高得点になったCoding Agentが、未知のPrivate Codebaseではトップでも4割未満という結果は、今のAgent能力を考えるうえでかなり健全なReality Checkです。([Y Combinator](https://www.ycombinator.com/companies/specific-labs))

ゲーム開発では **GodotのTexture Streaming**。Godot側では「Unity/Unrealなら当然あるProduction機能」を一つずつ埋めており、Engine競争という意味で追っておく価値があります。([Godot Engine](https://godotengine.org/article/dev-snapshot-godot-4-8-dev-5/))
