今朝はかなり豊作です。**Claude Fable 5.1 / Mythos 5.1、Gemini 3.8 Flash、OpenAI Astra** と、主要3社からほぼ同時に重要なモデル関連ニュースが出ました。一方、開発者として今日いちばん注意したいのは **AI Coding Agentを狙ったGitSpawn脆弱性**です。

---

## 1. Anthropic、Claude Fable 5.1 / Mythos 5.1を発表

[Anthropic公式発表](https://www.anthropic.com/claude-fable-and-mythos-5-1)

Anthropic が9月1日、**Claude Fable 5.1とClaude Mythos 5.1**を発表しました。同じ基盤モデルですが、Fable 5.1は一般提供、Mythos 5.1はCybersecurity・Life Sciencesなど高度な用途向けにTrusted Access方式で提供されます。AnthropicはCoding / Knowledge Workで同社最高性能としています。([Anthropic](https://www.anthropic.com/claude-fable-and-mythos-5-1))

特に実用面で面白いのが料金。**Cache Read価格を下げたことで典型的な処理はFable 5比で約25%、Agentic Workloadでは最大約45%安くなる**としています。([Anthropic](https://www.anthropic.com/claude-fable-and-mythos-5-1))

さらに [GitHub](https://github.com/) CopilotでもFable 5.1がGAになりました。([GitHub Blog](https://github.blog/changelog/2026-09-01-claude-fable-5-1-generally-available-in-github-copilot/))

**開発者目線:** Coding Agentは巨大Contextを何度も読み直すので、Benchmark差よりCache料金低下の方が実際のClaude Code運用コストには効く可能性があります。

---

## 2. Google、Gemini 3.8 Flash — 3週間でFlashをまた更新

[Google公式発表](https://blog.google/innovation-and-ai/models-and-research/gemini-models/3-8-flash-and-3-8-flash-cyber/)

Google が9月2日に **Gemini 3.8 Flash** を発表しました。

驚くのはリリース速度で、3.7 Flashからわずか3週間、**6週間で3回目のFlash更新**です。Googleは3.8を「これまでで最も優れたReasoning & Coding Model」と位置付けています。([blog.google](https://blog.google/innovation-and-ai/models-and-research/gemini-models/3-8-flash-and-3-8-flash-cyber/))

価格は3.7と同じ **入力$0.75 / 100万token、出力$3.75 / 100万token**。Software Engineering、Agentic Task、Multi-step Reasoningが重点的に改善されています。([blog.google](https://blog.google/innovation-and-ai/models-and-research/gemini-models/3-8-flash-and-3-8-flash-cyber/))

**開発者目線:** 高速・安価なモデルがCoding Agentで十分強くなってくると、

`難問 → Opus/Mythos級`
`通常実装 → Flash級`

というModel Routingがさらに有効になります。

## 3. Gemini 3.8にはCybersecurity専用「Flash Cyber」も

同時発表された **Gemini 3.8 Flash Cyber** は、Cybersecurity Agent用途へ特化したモデルです。([blog.google](https://blog.google/innovation-and-ai/models-and-research/gemini-models/3-8-flash-and-3-8-flash-cyber/))

ここはAnthropicのMythosと非常によく似た流れ。

汎用モデルを全ユーザーへ解放するのではなく、

**General Model + 高リスク専門Model + Access Control**

という製品構成になっています。

**開発者目線:** 「一つの万能LLMを使う」時代から、**Domainごとに専門ModelをAgentが選択する**構成へ進みそうです。

## 4. OpenAI「Astra」、Cyber能力が初のCritical水準へ

[OpenAI：Path to Astra](https://openai.com/index/path-to-astra/)

OpenAI が9月2日、次期モデル **Astra** のCybersecurity評価を公開しました。

OpenAIのPreparedness Framework上で初めて **Critical cybersecurity capability** に到達したモデルと判定されています。具体的には、適切なToolとAccessがあれば、人間が逐一指示せずとも未知の脆弱性を発見し、多くのHardeningされたSystemに対してExploitを構築できる水準です。([OpenAI](https://openai.com/index/path-to-astra/))

そのためOpenAIは一部の開発・Releaseを遅らせ、Safety Mechanismを強化したと説明しています。一般公開は「soon」ですが、高度なCyber能力へのAccessは制限されます。([OpenAI](https://openai.com/index/path-to-astra/))

**開発者目線:** LLM Securityが「Prompt Injectionを防ぐ」段階から、**モデル自身がZero-dayを探せることを前提にInfrastructureを設計する**段階へ来ています。

## 5. 要注意：悪意ある`.git/config`だけでCoding Agentから任意コード実行

今日一番実務的に重要です。

9月2日に **GitSpawn** と呼ばれる脆弱性群が公開されました。Claude Code、Codex、Cursor、Qwen Code、Grok Buildなど**7種類のCLI Coding Agentで8件の脆弱性**が発見されています。([The Hacker News](https://thehackernews.com/2026/09/malicious-git-configs-can-make-claude.html))

攻撃者はRepository内の`.git/config`に、例えばGitの`core.fsmonitor`として悪意あるCommandを設定します。

Agentが裏で、

`git status`
`git diff`

などを実行すると、**Agent Sandboxの外・ユーザー権限でCommandが実行される**ケースがありました。([The Hacker News](https://thehackernews.com/2026/09/malicious-git-configs-can-make-claude.html))

普通の`git clone`では`.git/config`はコピーされないため影響しませんが、**ZIP・共有Drive・同期Folder・USBなどで`.git`ごとRepositoryを受け取るケース**では注意が必要です。([The Hacker News](https://thehackernews.com/2026/09/malicious-git-configs-can-make-claude.html))

> [!WARNING]
> Claude Code / Cursorなど一部は修正済みですが、9月1日の再テスト時点で未修正Agentも残っています。([The Hacker News](https://thehackernews.com/2026/09/malicious-git-configs-can-make-claude.html))

**開発者目線:** 「怪しいRepositoryをAgentに読ませるだけならSandboxだから安全」と考えない方がよさそうです。

## 6. Anthropicが実利用データから「Agentの自律性」を調査

[Anthropic：Measuring AI agent autonomy in practice](https://www.anthropic.com/research/measuring-agent-autonomy)

AnthropicがClaude APIとClaude Codeの実データを使って、**人間が実際にAgentをどう監督しているか**を分析しました。

面白い結果があります。

Claude Code初心者はAgentの動作へ割り込むのが約5%なのに対し、経験者は**約9%まで増加**。一方で経験者ほどAuto-approveも増えます。([Anthropic](https://www.anthropic.com/research/measuring-agent-autonomy))

つまり、

> 慣れる → 全部Approveする

ではなく、

> **細かいApproveは減らすが、Agentを観察して必要なときだけ止める**

方向へ移っています。

またClaude自身が不確実な場合に質問する頻度は、人間がAgentへ割り込む頻度より高いことも確認されています。([Anthropic](https://www.anthropic.com/research/measuring-agent-autonomy))

**開発者目線:** Agent UIではPermission Dialogを増やすより、**今何をしているかを簡単に監視して即InterruptできるUI**の方が重要なのかもしれません。

## 7. GitHub Copilot CLI、「使えるモデルを複数指定してFallback」が可能に

Copilot CLI 1.0.83系のPre-releaseでは、Custom Agentの`model`へ**複数モデルを指定し、利用可能なものを順番に試す**機能が追加されています。`model-policy: required`で、そのList外への変更を禁止することもできます。([What's New](https://whatsnew.fyi/product/copilot-cli))

例えば概念的には、

`Fable 5.1 → Gemini 3.8 Flash → fallback model`

のようなPolicyをAgent側に持てます。

Linux SandboxではNetwork Egressを設定済みProxyへ限定する改善も入っています。([What's New](https://whatsnew.fyi/product/copilot-cli))

**開発者目線:** **「モデル名をWorkflowへ固定しない」設計が実際のCoding Agent機能として実装され始めた**のが面白いところです。

## 9. 小ネタ：AI Agent自身が操作できるTerminal「Unterm」

[Unterm](https://unterm.app/)

9月1日に **Unterm v0.71.2** が公開されています。

Claude Code、Codex、Gemini CLI、Aiderなどをまとめて起動できるLocal-first Terminalですが、面白いのはTerminal自身が**MCP Control Surface**を持つこと。([Unterm](https://unterm.app/))

Agentから、

`Terminal paneを開く`
`splitする`
`focusを変更する`
`別Agentを起動する`

といった操作ができます。

SessionはWindowとは別Processに保持され、GUIを閉じても生き続けます。Telemetryなし・Account不要・localhostのみで動作します。([Unterm](https://unterm.app/))

**開発者目線:** 「人間がTerminalでAgentを操作する」から、**AgentがTerminalそのものを操作する**という逆転が面白いです。まだ小規模OSSですが、今日の変なDeveloper Tool枠。

## 10. さらに小ネタ：Terminal Tool界隈が妙に元気

9月2日の新着だけでも、Terminal Toolまとめにはかなり面白いものが出ています。([ターミナル宝庫](https://terminaltrove.com/new/))

例えば **streamtop** はHLS / DASHなどのLive StreamをTerminalから監視するTool、**rwx**はUnix Permission / OwnershipをTUIで扱うTool、**reeve**はLocal Web Development StackをTUI化したもの、**mandible**はインストール済みCLIのManualをTerminalから探すToolです。([ターミナル宝庫](https://terminaltrove.com/new/))

**開発者目線:** Coding AgentがCLIを扱いやすいこともあり、GUI SaaSとは逆方向に**「ComposableなCLI/TUIを作る」文化が再び面白くなっています。**

## 👀 今日ならこの3つ

今日はまず **Fable 5.1 vs Gemini 3.8 Flash**。単純なBenchmark競争以上に、Claude側のCache値下げとGemini側の$0.75/M inputという価格を見ると、**Agentの推論コスト競争がかなり激しくなっている**のが重要です。([Anthropic](https://www.anthropic.com/claude-fable-and-mythos-5-1))

実務上は **GitSpawn** を最優先で知っておいた方がよいです。Coding Agentが裏でGit Commandを実行するという「便利な自動処理」がそのままAttack Surfaceになった、非常にAgent時代らしい脆弱性です。([The Hacker News](https://thehackernews.com/2026/09/malicious-git-configs-can-make-claude.html))

そして今後のAgent UXを見るなら **Anthropicの実利用調査**。熟練者が「細かくApproveする」より**Auto-approveしつつ監視して必要時だけInterruptする**方向へ進んでいるというデータは、Coding Agentの使い方を考えるうえでかなり参考になりそうです。([Anthropic](https://www.anthropic.com/research/measuring-agent-autonomy))
