今日は **ローカルCoding Agent** と **Open-weight coding model** が面白い日です。昨日扱ったDeepSeek Harness / A2A / Cursor Originなどは、続報が薄いので重複を避けました。

---

## 1. JetBrains「Junie Local」公開。Coding Agentを完全ローカル実行

[Junie Local公式発表](https://blog.jetbrains.com/junie/2026/08/junie-local-launch/)

JetBrains が8月24日、Coding Agent「Junie」をMac上だけで動かす **Junie Local** を公開しました。

`/local` だけでモデルを取得・起動し、コード・プロンプト・diffはマシン外へ出ません。初期版は **Qwen3.6-27B 4-bit、約20GB、M5 Mac + 64GB RAM** が要件です。JetBrainsはモデルをAgent用途向けに最適化した技術記事も同時公開しています。([The JetBrains Blog](https://blog.jetbrains.com/junie/2026/08/junie-local-launch/))

**気になる点:** 「ローカルLLMをAgentに接続できます」ではなく、IDEベンダー自身が **ローカル推論まで製品UXに統合**してきたのが大きいです。

---

## 2. Poolside、118BのCodingモデル「Laguna S 2.1」をOpen-weight化

8月24日に Poolside が **Laguna S 2.1** を公開。118Bパラメータで、特にAgentic Software Engineeringを狙ったモデルです。([HPCwire](https://www.hpcwire.com/aiwire/2026/08/24/poolside-launches-laguna-s-2-1-open-weight-coding-model/))

**気になる点:** DeepSeek HarnessやJunie Localと合わせて見ると、

**Open model + Agent harness + Local/Private inference**

という選択肢がかなり現実的になっています。

---

## 3. GPT-5.6がKiroに投入

[OpenAI公式発表](https://openai.com/index/gpt-5-6-in-kiro/)

8月24日、OpenAI のGPT-5.6ファミリー **Sol / Terra / Luna** が Kiro で利用可能になりました。([OpenAI](https://openai.com/index/gpt-5-6-in-kiro/))

**気になる点:** Coding Agent側が独自モデル一本で勝負するのではなく、用途・コストに応じて複数モデルを切り替える「Agentがモデルを使い分ける」構造がさらに普通になっています。

---

## 4. Claude Code、職場利用でCopilotを上回ったという調査

JetBrains Developer Ecosystem Survey 2026では、プロ開発者の **90%が週1回以上AI Coding Agentを利用**。さらに職場での利用ではClaude CodeがGitHub Copilotを上回ったと報告されています。([The JetBrains Blog](https://blog.jetbrains.com/research/2026/08/ai-coding-agent-adoption-2026/))

[JetBrainsの調査](https://blog.jetbrains.com/research/2026/08/ai-coding-agent-adoption-2026/)

**気になる点:** 補完中心だったCopilot型から、CLIでコードベース全体を扱う **Agent型ワークフローへの移行**が数字にもかなり表れてきました。

## 5. Asana「5年かかる想定だった移行をCodexで2週間」

[事例の詳細](https://openai.com/index/asana/)

Asana が、古いテスト基盤の置き換えにCodexを利用。従来見積もりでは約5年規模だった作業を **2週間、モデル＋インフラ費約$12,000** で完了したとOpenAIが8月19日に公開しました。([OpenAI](https://openai.com/index/asana/))

もちろんベンダー側の事例紹介なので数字は割り引いて見る必要があります。

**気になる点:** AIに新機能を書かせるより、**「価値はあるが人間がやるには費用対効果が悪すぎて放置されていた巨大リファクタリング」**にAgentを投入する使い方はかなり相性がよさそうです。

## 6. OpenAI、最先端モデルの開発ペースを一時的に落としたと公表

[OpenAI公式説明](https://openai.com/index/pacing-model-development-cyber-capabilities/)

OpenAIは8月19日、モデルのCyber能力向上に伴い、監視・Alignment・Security基準を満たすため **Scalingのペースを一時的に落とした**と説明しました。([OpenAI](https://openai.com/index/pacing-model-development-cyber-capabilities/))

Reutersも主要AI企業について、Agentの能力向上に対してContainment技術が十分追いついていないという第三者評価を報じています。([Reuters](https://www.reuters.com/technology/artificial-intelligence/ai-firms-cant-yet-contain-what-theyve-built-study-finds-2026-08-19/))

**開発者目線:** AgentのSandbox、権限分離、Tool permissionなどが単なるUX設定ではなく、本格的なSecurity boundaryになっています。

## 7. Hugging Faceに「130億ドル規模の買収打診」と報道

Hugging Face が買収提案を受け、**少なくとも130億ドル規模**の売却可能性を検討していると複数媒体が8月24日に報道しました。まだ成立した話ではありません。([Business Insider](https://www.businessinsider.com/hugging-face-could-be-acquired-13-billion-2026-8))

**気になる点:** Hugging Faceはモデル企業というより、モデル・Dataset・Inference・OSSコミュニティの**配布インフラ**に近い存在です。

AI競争で「モデルそのもの」だけでなく **モデルを流通させる場所**の価値が急上昇しているのが興味深いです。

## 8. Unity 6で「POSTAL 2」をほぼ作り直すプロジェクト

ちょっとゲーム開発小ネタ。

8月24日に発表された **POSTAL 2 Redux** は、2003年のUnreal Engine 1.5時代の素材をベースに、**Unity 6でゲーム全体を再構築**します。シームレスストリーミング、AI刷新、破壊可能環境なども予定されています。([フォーブス](https://www.forbes.com/sites/brianmazique/2026/08/24/postal-2-redux-announced-release-date-platforms-and-details/))

**Unity開発者目線:** 「Unity 6で20年以上前のゲームを現代的アーキテクチャへ再構築する」という、かなり珍しい実例になりそうです。

## 9. Unity公式の「大量Object Rendering」記事は読んでおいてよさそう

[Unity公式記事](https://unity.com/blog/rendering-at-scale-efficient-strategies-for-massive-object-counts)

Backyard Baseball 2026で、URP/HDRPの最適化から **独自Batch Renderer Groupによる草描画**まで行った実装事例が公開されています。([Unity](https://unity.com/blog/rendering-at-scale-efficient-strategies-for-massive-object-counts))

**Unity開発者目線:** 一般的な「GPU Instancingを使おう」程度ではなく、Unityの低レベルRendering APIまで降りているので、パフォーマンス改善の具体例として読み応えがあります。

## 10. Kotlinで「ComposeをSSRテンプレートとして使う」実験

[JetBrainsの技術記事](https://blog.jetbrains.com/kotlin/2026/08/exploring-compose-html-for-server-side-rendering/)

JetBrainsが **Compose HTMLをServer Side Renderingに使う**アイデアを実験しています。

つまりHTMLテンプレートを書く代わりに、型安全なKotlin + Compose ComponentでサーバーHTMLを生成する方向です。まだ正式ロードマップではなく、明確に「exploration」とされています。([The JetBrains Blog](https://blog.jetbrains.com/kotlin/2026/08/exploring-compose-html-for-server-side-rendering/))

**気になる点:** JSX/Reactとは逆方向から、JVM Backend側が「テンプレート言語をなくしてUIも普通のコードにする」アプローチ。今日の**小ネタ枠ではかなり好きな話**です。

---

## 👀 今日ならこの3つ

**Junie Local**は一番触ってみたいです。要求スペックはまだ高いものの、「Coding Agentを完全ローカルで普通に使う」UXが製品として出てきたのは大きな変化です。

次に **Asana × Codex**。Agentの有効活用先として「新規コード生成」より**巨大な技術的負債の返済**が有望、という実例として面白いです。

そして小ネタなら **Compose HTML SSR**。こういう「まだ流行ってはいないけれど、数年後に普通になっているかもしれない技術」も面白い題材です。
