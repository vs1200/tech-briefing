昨日までに扱ったNVIDIA × Hugging Face、PAIR、TeamCity MCPなどはなるべく外しました。今日は **GPT-6 Astraの実利用開始、VS CodeのAgent Merge、Cloud Agent用Sandbox、Supply Chainまわり**が面白いです。

---

## 1. GPT-6 Astra、GitHub CopilotでもGA

9月4日、[GitHub](https://github.com/) Copilotで GPT-6 Astra が一般提供になりました。前日に紹介したAstraが「発表されたモデル」から、普段のCoding Workflowで実際に選べるモデルになった形です。([The GitHub Blog](https://github.blog/changelog/2026-09-04-gpt-6-astra-is-generally-available-in-github-copilot))

[GitHub公式：GPT-6 Astra in Copilot](https://github.blog/changelog/2026-09-04-gpt-6-astra-is-generally-available-in-github-copilot)

**開発者目線:** AstraはCodingとComputer Useを強く意識した世代なので、単純なコード生成より、Repository探索・Tool利用・長い実装タスクで旧世代との差が出るかを見たいところです。特にFable 5.1 / Gemini 3.8 Flashとの実タスク比較がこれから面白くなります。

---

## 2. VS Code 1.136「Agent Merge」— レビュー後の面倒な後処理までAgentへ

今週のCopilot更新で個人的にかなり気になるのが **Agent Merge** のPublic Previewです。

PRに対してAgentが、**Review Feedbackへの対応、Failed Checkの修正、Merge Conflict解消**を行い、「Mergeできる状態」まで持っていきます。さらにAgent Sessionを階層表示して、どのSessionが人間のAttentionを必要としているかも整理されるようになりました。([The GitHub Blog](https://github.blog/changelog/2026-09-04-github-copilot-weekly-releases-august-31))

**開発者目線:** Coding Agentの仕事が、

`Issue → 実装 → PR`

で終わらず、

`Review → CI失敗 → Conflict → 修正 → Merge-ready`

まで伸びています。人間側はますます「コードを書く人」より**複数PR/AgentのSupervisor**に近づきます。

---

## 3. VS Code、Multi-root Workspaceでも複数Agent Session

同じVS Code 1.136では、Multi-root WorkspaceでCopilot / ClaudeのAgent Sessionを各Folderに持たせる機能がExperimentalで入りました。([The GitHub Blog](https://github.blog/changelog/2026-09-04-github-copilot-weekly-releases-august-31))

例えば、

`game-client/`
`backend/`
`tools/`

のような複数Repositoryを1 Workspaceで扱い、それぞれ別Agent Sessionを走らせる方向です。

**開発者目線:** Client + Server + Toolのような構成ではかなり実用的。Agent時代のIDEは「1つのChatがRepositoryを全部見る」より、**責務ごとにContextを分割して並列実行する**方向へ進みそうです。

---

## 4. Cloudflare Sandbox × Cursor Cloud Agents

Cloudflare がCursor Cloud AgentsをCloudflare Sandbox上で動かす構成を公開しています。Cloud Agentごとに隔離環境を用意し、RepositoryをCloneしてCommandやTestを実行させます。([Techzine Global](https://www.techzine.eu/blogs/devops/144065/cloudflare-sandboxes-cursor-cloud-agents-developers/))

**開発者目線:** Agent Runtimeの競争がかなり面白くなっています。

`Coding Agent`
↓
`Ephemeral Sandbox`
↓
`git clone → build → test → destroy`

という構成が定番化しつつあります。

Docker Containerを自前管理するより、**Agent実行専用SandboxをInfrastructure Serviceとして借りる**方向です。

## 5. npm Trusted Publishing、1 Packageに複数構成を設定可能に

GitHubは9月3日、npm向けTrusted Publishingを拡張しました。1つのPackageに複数のTrusted Publisher Configurationを設定できます。([The GitHub Blog](https://github.blog/changelog/2026-09-03-multiple-trusted-publishing-configurations-for-npm))

例えばRelease Workflowだけでなく、異なるRepository / Workflowから安全にPublishする構成を作りやすくなります。

**開発者目線:** 長寿命の`NPM_TOKEN`をGitHub Secretsへ保存するより、OIDCによる短命Credentialを使うTrusted Publishingの方がSupply Chain Attackへの耐性があります。

Coding AgentがCI/CDまで触るようになるほど、**「SecretをAgentから隠す」のではなく、そもそも永続Secretをなくす**設計が重要になります。

## 6. CodeQL 2.26.4、GitHub Actions自体の脆弱な書き方をさらに検出

GitHubがCodeQL 2.26.4を公開し、GitHub Actions Workflow向けSecurity Detectionを強化しました。([The GitHub Blog](https://github.blog/changelog/2026-09-03-codeql-2-26-4-improves-github-actions-security-detections))

最近はApplication Sourceだけでなく、

`pull_request_target`
`workflow_run`
`untrusted input → shell`

など、**CI WorkflowそのものがAttack Surface**になるケースが増えています。

**開発者目線:** AgentがWorkflow YAMLまで自動生成・修正する時代なので、Code Reviewだけでなく「CI設定をStatic Analysisする」価値がかなり上がっています。

---

## 7. GitHub Actions、9月前半の細かい改善がまとまって入る

GitHub Actionsにも複数の改善が9月3日に入りました。([The GitHub Blog](https://github.blog/changelog/2026-09-03-github-actions-early-september-2026-updates))

派手な新製品ではありませんが、Runner / Workflow運用周辺が継続的に更新されています。

**開発者目線:** AgentがPRからCIまで操作する流れを見ると、GitHub Actionsは単なるCIではなく**Coding Agentの実行・検証Backend**として重要度が上がっています。Agent Mergeの「Failed Checkを見て修正」もこのLayerと直結しています。

## 8. ArmorPaint 1.0 — 8年のEarly Accessを経て正式版

ゲーム開発・CG枠ではこれが面白いです。

Open-source 3D Texture Painting Tool **ArmorPaint 1.0** が正式リリースされました。約8年間のEarly Accessを経た大型節目です。([CGチャンネル](https://www.cgchannel.com/2026/09/armorpaint-1-0-is-out-after-eight-years-in-early-access/))

1.0ではSoftware CoreをCで書き直し、Performanceを改善。より巨大な3D Assetや、高解像度Texture LayerをInteractiveに扱えるようになっています。([CGチャンネル](https://www.cgchannel.com/2026/09/armorpaint-1-0-is-out-after-eight-years-in-early-access/))

**ゲーム開発者目線:** Substance 3D Painter系WorkflowのOSS代替候補です。Unityプロジェクトで「Artist ToolまでAdobe依存したくない」という場合には一度触る価値があります。

## 9. IntelliJ IDEA 2026.2.2リリース

IntelliJ IDEA 2026.2.2が9月2日に公開されています。Toolbox AppやIDE内から更新可能です。([The JetBrains Blog](https://blog.jetbrains.com/idea/2026/09/intellij-idea-2026-2-2/))

大型新機能というより2026.2系列のMaintenance Releaseですが、JetBrains系IDEを仕事で使うなら実用ニュース枠。

**開発者目線:** 最近JetBrainsはIDE本体、Junie、MCP、Local Agent、Kotlin Toolchainをかなり速いペースで並行更新しています。従来型IDEにAgentを後付けするのではなく、**IDE PlatformそのものをAgent対応させる**動きは継続して追いたいです。

## 10. 今日中に注意：GitHub CLIのLinux Package Signing Keyが期限切れ

これは小ネタではありますが、Linux環境を持っているなら実務的です。

GitHub CLIのLinux Repositoryで使われているPackage Signing Keyが**今日9月5日に期限切れ**になります。GitHubは新しいKeyへの更新手順を案内しています。([The GitHub Blog](https://github.blog/changelog/2026-09-03-github-cli-linux-package-signing-key-expires-september-5))

[GitHub公式：Signing Key更新案内](https://github.blog/changelog/2026-09-03-github-cli-linux-package-signing-key-expires-september-5)

**開発者目線:** CI ImageやDockerfileでGitHub CLI Repositoryを登録している場合、古いKeyを焼き込んだままだと今後の`apt update`等で問題になる可能性があります。手元ではMacを使っていても、Linux CI環境は一応検索しておくとよさそうです。

## 👀 今日ならこの3つ

一番面白いのは **Agent Merge** です。Agentが「コードを書く」ところはかなり成熟してきましたが、現実の開発で時間を食うのはその後の**レビュー指摘・CI失敗・Conflictへの細かな対応**。ここを丸ごとAgentへ渡せるなら、Coding Agentの実用価値が一段上がります。([The GitHub Blog](https://github.blog/changelog/2026-09-04-github-copilot-weekly-releases-august-31))

次は **Cloud Agent × Ephemeral Sandbox**。Coding AgentにShell権限を渡す問題への現実的な回答として、「Developer PCで安全に動かす」より**使い捨て環境へAgentごと閉じ込める**設計がかなり有力になってきました。([Techzine Global](https://www.techzine.eu/blogs/devops/144065/cloudflare-sandboxes-cursor-cloud-agents-developers/))

ゲーム開発では **ArmorPaint 1.0**。実際に制作Pipelineへ入り得るOSS Toolです。
