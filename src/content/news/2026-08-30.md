## 1. Google「Cloud Run instances」— 月$5.70で常駐AI Agent

[Google Cloud公式発表](https://cloud.google.com/blog/products/serverless/introducing-cloud-run-instances)

Google が8月27日に **Cloud Run instances** をPreview公開しました。

従来のCloud Runはリクエストがなくなるとscale-to-zeroするので、「24時間生き続ける個人Agent」とは少し相性が悪い。一方、新しいinstancesは **1インスタンス固定・最大7日連続実行・固定HTTPS URL・自動再起動**という設計です。1 vCPU / 1 GiBなら30日連続稼働の目安が**月$5.70**とされています。([Google Cloud](https://cloud.google.com/blog/products/serverless/introducing-cloud-run-instances))

公式例も面白く、OpenClawのようなPersonal AgentをCloud Runへ置き、TelegramやWhatsAppなどから呼び出す構成を紹介しています。

**開発者目線:** Agent用Infrastructureが「KubernetesかVMを用意する」から、**Agentそのものを1個常駐させるServerless Primitive**へ変わり始めています。

**気になる度：★★★★★**

## 2. NVIDIA「Open Model → TensorRT」を2コマンドに

[NVIDIA Technical Blog](https://developer.nvidia.com/blog/recent-posts)

NVIDIA が8月28日、**TensorRT Model Connect**を紹介しました。

Open-weight modelをNative Applicationで使おうとすると、従来はモデル固有の変換・Pre/Post Processing・TensorRT対応などが必要でした。それを、

**Checkpoint → TensorRT Engine → Inference**

までかなり自動化し、**2コマンドで持っていく**ことを狙っています。([NVIDIA Developer](https://developer.nvidia.com/blog/recent-posts))

**開発者目線:** Hugging Faceからモデルを落として「手元のアプリに組み込む」までの壁がまた一段低くなっています。

ゲーム内推論・ローカルTool・Edge AIを自作する人には結構重要そうです。

**気になる度：★★★★★**

## 3. Claude Code、9月14日から恒久的に週次上限+25%……ただし現在よりは減る

Anthropic がClaude Codeの週次利用上限を、**9月14日から従来標準値比で25%引き上げる**方針を明らかにしました。

ただし現在は一時的に+50%されているため、

`元々：100`
`現在：150`
`9/14以降：125`

という関係。

つまり**現在比では約17%減**です。現在の+50%キャンペーンは9月13日まで続くと報じられています。([BleepingComputer](https://www.bleepingcomputer.com/news/artificial-intelligence/anthropic-is-cutting-claude-codes-current-weekly-limits-by-17-percent/))

**開発者目線:** Claude Codeを長時間回す場合、モデル性能だけでなく**Token Budget / Usage Limit自体が開発Infrastructureの制約**になっています。

**気になる度：★★★★★**

## 4. Microsoft、WinUIの本流開発をGitHubへ移行

[WinUI GitHub](https://github.com/microsoft/microsoft-ui-xaml/discussions/10700)

Microsoft がWinUI / Windows App SDKについて、よりOpenなGitHub中心の開発へ移行を進めています。8月29日にもこの動きが改めて注目されています。([Thurrott.com](https://www.thurrott.com/dev/340841/microsoft-moves-winui-wasdk-development-to-github))

これまで「WindowsのUI Frameworkなのに、実際の開発過程が外から見えづらい」という不満がありましたが、Issueだけでなく**mainline developmentそのものをOSS的に見せる**方向です。

**開発者目線:** Windows Native UIがElectron/WebView一辺倒にならず、Microsoft自身がWinUIをもう一度Developer Platformとして育てようとしている点が面白いです。

**気になる度：★★★★☆**

## 5. AWS：「AI時代はLegacy Migrationを“一度だけ”やるのをやめよう」

[AWS公式：Continuous Modernization](https://aws.amazon.com/blogs/devops//)

8月28日に Amazon Web Services が **Continuous Modernization Pipeline** という考え方を公開しました。([Amazon Web Services, Inc.](https://aws.amazon.com/blogs/devops//))

従来、

`古くなる → 巨大Migration Project → 数年後また古くなる`

だったものを、

`コード変更 → AI Modernization → Test → 継続的に更新`

というPipelineへしてしまおう、という発想です。

**開発者目線:** Coding Agentの使い道として「新機能を速く書く」より、**放置されている技術的負債を常時返済する**方が組織的なROIは大きい可能性があります。

**気になる度：★★★★☆**

## 7. GitHub Classroom、8月28日で終了

[GitHub公式告知](https://github.blog/changelog/2026-05-26-github-classroom-sign-ups-are-no-longer-available/)

**開発者目線:** GitHubが「自社ですべてのDeveloper Serviceを持つ」のではなく、Core Platform + Partner ecosystemへ整理している動きとして見ると興味深いです。

**気になる度：★★★☆☆**

## 8. 「AI時代には巨大IDEいらないのでは？」というLithe IDE

今日のOSS小ネタ。

[Lithe IDE GitHub](https://github.com/1lck/Lithe-IDEA)

**Lithe**という軽量Cross-platform IDEが、「CodexやClaude Codeが実装するなら、人間用IDEに全部の機能を常駐させる必要はあるのか？」という発想で開発されています。([GitHub](https://github.com/1lck/Lithe-IDEA))

人間が必要なのは主に、

`コードを読む`
`Symbolを追う`
`Debugする`
`DiffをReviewする`

なので、それだけを軽量に提供し、ToolやServiceを必要時に起動する設計です。

**開発者目線:** 昨日紹介したAgent用Diff Viewerとも同じ流れ。

**「IDE = コードを書く場所」から「Agentが書いたものを理解・検証する場所」へ**

という再設計は今後かなり面白くなりそうです。

**気になる度：★★★★☆**

## 9. UnityのRender Pipeline方針を改めて確認：Built-Inは6.5からDeprecated

今日は新しいUnityリリースが薄かったので、最近更新された重要な技術方針を一つ。

[Unity公式：Render Pipelines strategy for 2026](https://unity.com/topics/render-pipelines-strategy-for-2026)

Unity は2026年のRender Pipeline戦略を、

**URP → 開発リソースを集中**
**HDRP → Platform拡大と安定性中心**
**Built-In → Unity 6.5から正式Deprecated**

としています。([Unity](https://unity.com/topics/render-pipelines-strategy-for-2026))

Built-Inは少なくとも**Unity 6.7 LTSまでは残る**ものの、新規タイトルでは明確に非推奨です。最終削除Versionはまだ決まっていません。

Unity 7でもURPが中心になるため、今後のRendering系技術投資はかなり一本化されます。

**Unity開発者目線:** 新規LibraryやAssetを作る場合も、Built-In互換へコストを掛ける価値は急速に下がっています。

**気になる度：★★★★☆**

## 10. Agent Skill、ついに「1000個以上を集めたAwesome List」まで登場

最後は軽め。

[Awesome Agent Skills](https://github.com/VoltAgent/awesome-agent-skills)

**awesome-agent-skills**というRepositoryでは、Claude Code、Codex、Gemini CLI、Cursorなどで利用できるAgent Skillを**1000以上**まとめています。([GitHub](https://github.com/VoltAgent/awesome-agent-skills))

面白いのは単なるPrompt集ではなく、最近のSkillは、

`workflow`
`reference`
`script`
`tool/MCP`
`domain knowledge`

などを一つの再利用可能なPackageとして扱う方向になっていること。

AWSもAgent Pluginを **Skill + MCP + Hook + Reference** のContainerとして定義しています。([Amazon Web Services, Inc.](https://aws.amazon.com/blogs/developer/introducing-agent-plugins-for-aws/))

**開発者目線:** npm packageのように、**「Agentに能力をinstallする」ecosystem**が本当に形成され始めています。

**気になる度：★★★★☆**

## 👀 今日ならこの3つ

今日は **Cloud Run instances** が一番おすすめです。常駐Agent専用に近いInfrastructure PrimitiveがGoogle Cloudから出てきたことで、「自分専用Agentをどこで24時間動かす？」への回答がかなり簡単になりました。([Google Cloud](https://cloud.google.com/blog/products/serverless/introducing-cloud-run-instances))

次に **TensorRT Model Connect**。Open-weight modelは「Weightが公開されている」だけでは使いづらかったのですが、**ModelをApplicationへ載せる最後の1km**がどんどん自動化されています。([NVIDIA Developer](https://developer.nvidia.com/blog/recent-posts))

そして個人的に面白いのは **Lithe IDE**。Agentがコードを書く量が増えるほど、人間向けDeveloper Toolは「入力効率」より**理解・Navigation・Review・Debug効率**が重要になるはずです。ここは2026年後半に新しいToolがかなり出てきそうです。
