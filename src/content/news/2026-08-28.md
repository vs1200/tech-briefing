今朝は **「Coding Agentをどう実運用するか」** が中心です。昨日までに扱ったA2A、Cursor Origin、ローカルAgentなどの重複は避け、**8月27日前後に新しく出てきた話**を多めに拾いました。

---

## 1. Uber、PRの70%以上にAIが関与する「Software Factory」の実態を公開

[Uber公式：Running a Software Factory Efficiently at Uber Scale](https://www.uber.com/us/en/blog/efficient-software-factory/)

Uber がかなり面白い開発体制の記事を公開しています。

Uberでは現在、**Pull Requestの70%以上がローカルまたはCloud Coding Agent由来**。AIを単なるコード生成ではなく、実装・レビュー・テスト・CIなど開発ライフサイクル全体へ組み込んでいます。([Uber](https://www.uber.com/us/en/blog/efficient-software-factory/))

ここまで来ると「Claude Codeを使うか？」ではなく、

`人間 → Issue/設計 → Agent群 → PR → Agent Review → CI → 人間`

という**Software Factoryそのものをどう設計するか**の問題になります。

**開発者目線:** 大規模組織でCoding Agentをどう運用するかという実例として、今日一番おすすめの記事です。

## 2. AWSが「Agent Toolkit」を公開 — AgentにAWS専門知識をSkillとして渡す

Amazon Web Services が **Agent Toolkit for AWS** を公開しました。Claude CodeなどのCoding Agentに、AWS固有の設計・デプロイ・トラブルシューティング手順を与える仕組みです。([ADTmag](https://adtmag.com/articles/2026/08/27/aws-toolkit-gives-coding-agents-specialized-cloud-development-skills.aspx))

方向性として重要なのは、

**万能なモデルをさらに賢くする**

のではなく、

**既存Agent + AWS専門Skill**

にしていること。

ここ数週間のAgent Plugins / Skills / MCPの流れと完全につながっています。

**開発者目線:** チーム内のUnityやCI/CDのノウハウも同じように「Skill化する」という発想がかなり現実的になってきました。

## 3. Eclipse Theia、「AI First IDE」というかなり攻めたUIを実験

[Eclipse Theia公式](https://www.eclipse.org/lists/theia-dev/msg00370.html)

Eclipse Theia 1.74では、実験的な **AI First perspective** が追加されています。

従来の

`Editorが中心 + 横にAI Chat`

ではなく、

**AI Chat / Agent SessionをIDEの中心に置く**

設計です。

さらにSession単位のモデル選択、Multi-Agent Session、長時間Agent用のServer-side Context Compactionなども入っています。([エクリプスニュース](https://newsroom.eclipse.org/))

**開発者目線:** VS Code / Cursorのさらに先で、IDE自体が「Agent Manager」になったらどうなるかを見る実験として面白いです。

## 4. Google「Gemini Omni 1.1 Flash」— 動画生成をAPIから細かく制御

[Google公式発表](https://blog.google/innovation-and-ai/technology/developers-tools/build-with-gemini-omni-1-1-flash/)

Google が8月27日、**Gemini Omni 1.1 Flash** を開発者向けに公開しました。

特徴は単なるText-to-Videoではなく、Reference Imageや編集指示などを使って**生成結果をかなり細かく制御できる**ことです。([blog.google](https://blog.google/innovation-and-ai/technology/developers-tools/build-with-gemini-omni-1-1-flash/))

**ゲーム開発目線:** AI Asset生成は「一発で画像を作る」段階から、既存Assetを保持しながらvariationを生成する**制作Pipelineの一工程**へ移りつつあります。

## 5. Android、AIによるDRAM不足を受けて「メモリ節約」をさらに要求へ

[TechCrunchの解説](https://techcrunch.com/2026/08/27/ais-memory-crunch-is-coming-for-android-apps/)

少し意外なところでAIブームの影響が出ています。

AI Data Center需要によるメモリ市場の逼迫を背景に、GoogleがAndroidアプリのメモリ使用量について新たな対策を進めています。([TechCrunch](https://techcrunch.com/2026/08/27/ais-memory-crunch-is-coming-for-android-apps/))

つまりAIの影響が、

`GPU不足 → HBM不足 → DRAM市場 → スマホ → アプリのMemory Budget`

まで降りてきています。

**開発者目線:** モバイルゲームではTexture、AssetBundle、Managed HeapなどのMemory管理が再び強く意識される可能性があります。

## 7. 「AI Code ReviewはAgent数を増やせば良いわけではない」という研究

ICML 2026で発表された研究について、**3 AgentによるStructured Disagreement型レビューが5 Agent構成を上回った**という結果が話題になっています。([Intelligent Living](https://www.intelligentliving.co/adversarial-code-review-ai-agents/))

ポイントは、

`Agent A：問題を指摘`
`Agent B：反論`
`Agent C：両者を評価`

のように**役割と議論構造を与えること**。

単純に5個のLLMへ「レビューして」と投げて多数決するより良い結果になったとされています。

**開発者目線:** Multi-Agent設計では「Agent数」より**Agent同士をどう議論させるか**の方が重要、という示唆があります。

## 8. AI Coding Toolを装ったMac Malwareが増加

[The Registerの報道](https://www.theregister.com/security/2026/08/25/crooks-push-mac-malware-through-fake-openai-codex-ads/5291899)

OpenAI Codexなどを検索すると、Sponsored Search Result経由で偽サイトへ誘導され、MacへMalwareを入れさせる攻撃が確認されています。([theregister](https://www.theregister.com/security/2026/08/25/crooks-push-mac-malware-through-fake-openai-codex-ads/5291899))

AI ToolはCLIインストールが多いので、

> Terminalを開いてこのCommandを貼ってください

という誘導が自然に見えてしまうのが厄介です。

**開発者目線:** Coding Agent / MCP / CLIツールは、できれば公式RepositoryやPackage Manager経由で導入した方が安全です。

## 9. Unity 6.0 LTS、6000.0.82f1が出ています

[Unity 6000.0.82f1 Release Notes](https://unity.com/ja/releases/editor/whats-new/6000.0.82f1)

**Unity開発者目線:** Unity 6系を使っているなら、派手なUnity 7ニュースとは別にLTS Patchの追跡は続けた方がよさそうです。

## 10. NVIDIAの四半期売上、ついに962億ドル

[NVIDIA公式決算](https://nvidianews.nvidia.com/news/nvidia-announces-financial-results-for-second-quarter-fiscal-2027)

NVIDIA がFY2027 Q2決算を発表し、四半期売上は **962億ドル**。前四半期比18%増となりました。([NVIDIA Newsroom](https://nvidianews.nvidia.com/news/nvidia-announces-financial-results-for-second-quarter-fiscal-2027))

単なる株ニュースとしてではなく、Developer視点で面白いのは、これだけ巨額のCompute需要がある一方で、NVIDIA自身もOpen ModelやLocal AIをかなり強く推していることです。([NVIDIA Blog](https://blogs.nvidia.com/blog/local-ai-open-source-models-agents-nemotron/))

**開発者目線:** Cloud API一択ではなく、

`巨大モデル → Cloud`
`Coding/Agent用中型モデル → Local GPU`
`小型モデル → Edge`

という**Inferenceの棲み分け**がかなり明確になってきています。

## 👀 今日ならこの3つ

今日は **UberのSoftware Factory** が頭ひとつ抜けて面白いです。PRの70%以上にAgentが関与するところまで行くと、「AIにコードを書かせるTips」ではなく、**開発プロセスそのものをAgent前提で再設計する話**になります。([Uber](https://www.uber.com/us/en/blog/efficient-software-factory/))

次に **AWS Agent Toolkit**。このところ続いている Skill / Plugin / MCP の流れを見るうえでかなり象徴的で、「強い汎用Agent + 組織やDomain固有のSkill」という構成が2026年後半の定番になりそうです。([ADTmag](https://adtmag.com/articles/2026/08/27/aws-toolkit-gives-coding-agents-specialized-cloud-development-skills.aspx))

小ネタならもちろん **Hugging FaceのOSSアヒルロボット**。重要ニュースではないものの、技術者として妙に気になる話題です。
